# ClawKit Desktop 3.20.2 大附件优化

ClawKit 原生 Codex Responses 请求在本地代理完成最终序列化后，超过 40 MiB 才处理附件。
目标为 38 MiB；原图与不带 filename 的 PDF 的字节保持不变，只把必要的内嵌附件替换为临时网关 URL。
不处理纯文本、其他协议、其他模型服务地址，也不调整模型、工具、图片 detail 或对话历史。
当前云端能力限定 `gpt-6.1-sol`，其他模型按原接口转发。

## 使用与延迟

“手机远程 → 可选：使用 ClawKit 模型服务”提供“大附件优化”开关。新的一键配置默认启用。
已有一键配置且当前供应商为 ClawKit、服务地址为 ClawKit 网关的用户，应用启动时接入既有本地代理。
切换到其他供应商不会触发自动接管。ClawKit 必须保持运行；恢复配置可恢复一键配置前的供应商和路由。
关闭开关会停止附件外置，当前代理路由仍可继续使用。

40 MiB 以内不请求附件接口。超限时缓存优先，再按可节省的字节数选择附件；两路并发上传。
完整 SHA-256 与 MIME 去重；同一账号有效链接缓存最多 512 项，链接剩余不足 5 分钟时重新授权。
首次上传增加传输和校验时间；重复请求复用缓存。总准备时限 90 秒，最多两次并行大请求准备。
不压缩画质，不降低图片 token；上下文超限仍须由调用端处理。

## 私有存储与失败行为

客户端持 API Token 向 New API 获取 5 分钟临时 COS PUT 授权，不持有存储密钥。
上传 staging 后，New API 核验精确尺寸、SHA-256、MIME 和图片尺寸或 PDF 文件头。
校验后的原字节发布到另一个客户端无覆盖权限的对象键，返回 30 分钟网关签名读取 URL。
New API 使用可信元数据估算图片 token，普通 URL 保留 SSRF 检查。
对象最长 24 小时、未完成上传 staging 15 分钟后进入清理队列。

所有选中附件验证通过后才修改请求。准备失败返回 `clawkit_attachment_upload_failed`，模型请求不发送；
可处理附件不足则返回 `clawkit_payload_too_large`。单个附件上限 20 MiB，图片不超过 100 MP。
本地 Responses 入站和解压后上限 128 MiB。

跨进程缓存可能丢失并发写入的个别回执；这只影响缓存命中，服务端仍独立校验和隔离账号。
临时链接是持有即可读取的授权，应视为敏感值；请求捕获和网关日志删除可用签名。
集中日志仅异步上报大小、外置数量、准备耗时，不记录附件内容或链接。

## 验证与发布

相关 Rust 场景覆盖 44 图超限、只外置必要附件、重复缓存、具名 PDF 保留原内嵌字段、失败原子性、
一键配置、重启与恢复配置。发布回执另记准确源码 SHA、构建设备、测试输出、产物摘要和回滚版本。

Responses 上游拒绝 `filename` 与 `file_url` 同时出现；带 filename 的 PDF 保持内嵌，不删除名称来规避错误。
