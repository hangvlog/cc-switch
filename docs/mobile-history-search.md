# ClawKit Mobile 0.1.25: history search and visible progress

Searching a phrase from a previously sent user message returned no chats in 0.1.24: the phone only filtered names, initial prompts and directories. Mobile 0.1.25 adds debounced historical user-message search through Desktop 3.19.45. Results include a matching snippet and open the matching saved-history page. Title/project matches remain available while the history index is being populated; old bridges explicitly request an upgrade instead of presenting incomplete results as a successful search.

The desktop builds an incremental, on-demand SQLite cache from eligible original transcripts. Only visible user-message events are indexed; system/developer context, assistant reasoning, tool output and assistant answers are excluded. Transcript identities and canonical paths are verified. Each request has a read budget, each record a memory limit, and partial writes are retried on subsequent searches. Progress and unavailable-file counts are returned. The cache stays under the account-scoped bridge storage, with private permissions on macOS. The relay receives only the query and matching snippets, never the full index. At most 100 matching chats are returned, with a total count and a suggestion to refine the query.

The sidebar now searches project names consistently, supports whitespace-separated terms, shows results independently of grouping metadata, publishes each catalog page immediately, shares concurrent refresh requests, and distinguishes incomplete loading/errors from no matches. During an active turn, the most recent progress message is fully expanded and live text replaces stale paginated text.

Validation before release: reproduce the old search on the real catalog using “在微信、浏览器等其他应用里复制” (zero results), then search original local history and open the matching history cursor. 402 transcripts indexed into a 2,953,216-byte cache; the first debug-build scan took 179 seconds and returns early matches/progress throughout. This is a debug measurement, not a production performance guarantee. Focused Rust and mobile regression tests and TypeScript compilation cover the changed paths. Native UI and published artifact checks are recorded in the release manifest. Android physical-device acceptance remains with the user.

The requested desktop/mobile unread green-dot synchronization is tracked separately: the current official desktop does not accept the read-state IPC broadcast used in the probe. This release does not claim bidirectional unread synchronization. Rollback: Mobile 0.1.24 / Desktop 3.19.44. Desktop manual installers remain outside the automatic feed until the original updater signing key is available.

Desktop 3.19.46 exposes `threadStatuses` and bounded `desktop/thread/statuses` for Mobile 0.1.26 sidebar running indicators. Each request accepts at most 32 eligible IDs, uses four passive IPC readers and returns only ID/status plus observation time. Active, idle, waiting, error and unknown remain distinct; no dormant task is opened.
