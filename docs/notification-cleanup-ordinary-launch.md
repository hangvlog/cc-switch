# 跨端通知清理与 Mac 普通启动接入

范围：`ide-heleper/codex-mobile` 0.1.57 与独立源仓 `ide-heleper/cc-switch` 3.19.69。不修改官方 Codex 安装包、云端业务数据或正在运行的官方进程。

## 通知行为

- 手机读到任务结果时，按账号、电脑、会话和阅读时间清理已有完成通知；较新的结果继续提醒。
- 审批与问题需真正处理后撤销。桌面原始引擎的响应与 serverRequest/resolved 更新对应通知，SQLite 保留处理状态；历史通道通过官方 owner 的被动快照或任务完成记录核对。
- 在电脑读过结果也会同步撤销完成通知。使用当前账号的官方未读状态，完成后保留 10 秒状态传播缓冲。缺少可靠状态时保留提醒，不推测已读。
- Android 原生后台连接先消费 resolved，再进行通知去重，已显示/已经 seen 的通知仍可撤销。正常在线轮询约 15 秒；断线重连后再次核对。常驻连接通知及其他任务不受影响。
- 手机本地阅读截止时间有跨进程文件锁，避免后台发通知与前台清理竞争。仅保存有界标识和时间，不保存消息正文。

## Mac 正常打开 Codex

启用手机远控后，ClawKit 后台服务给当前用户登录会话设置自己的 CODEX_CLI_PATH 与官方引擎路径，Dock/Finder 正常启动即复用同一 stdio 适配器。登录后恢复配置，关闭远控时仅移除属于本安装位置的变量，不覆盖用户自定义 CLI 配置。

已经运行的 Codex 不会被重启，旧进程也不能热接入 stdio。当前任务结束后自然退出、正常重开一次才获得新建通道，此后无需通过 ClawKit 按钮启动。活动视图依赖专用启动时的渲染通道，仍有差异；不宣称所有能力完全一致。命令行启动器显式覆盖环境变量时也应以实际 capability 为准。

## 验证与发布

最小测试覆盖：处理一个审批不影响另一个、处理状态重启持久化、账号隔离、桌面未读到已读的完成通知转换。普通启动隔离官方实例已验证创建、项目归属、原引擎回复和重复请求抑制。Android 安装包原生通知撤销及线上发布结果记录在同版本 release JSON；构建成功不代表实体手机验收。
